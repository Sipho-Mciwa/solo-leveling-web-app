# Coach Suggests — Single-Select + Actionable Checklist — Design

## Problem

The "Coach Suggests" card (`frontend/components/ChallengeSection.tsx:122-151`) shows 2 AI-generated
suggestions per day. Today both are independently tappable through the same
accept → complete lifecycle (`acceptAISuggestion` / `completeAISuggestion` in
`frontend/lib/api.ts:162-173`, backed by `acceptChallenge` /
`completeAISuggestion` in `backend/services/ai.service.js:225-298`) with no
constraint preventing a user from accepting *both*, and no guidance on what
"complete" actually requires beyond a single tap. The user wants: (a) picking
one suggestion locks out the other for the day, and (b) accepting a
suggestion generates an AI checklist of concrete steps, which must be fully
checked off to complete it and claim the XP.

## Decision

1. **Single-select via a transactional invariant**, not new state. Reuse the
   existing `status` field and `acceptChallenge` transaction — no new
   "select" concept.
2. **Checklist is a new `subtasks` array** on each suggestion, generated by a
   second AI call triggered right after a successful accept (two backend
   requests chained by the frontend, one user-facing action).
3. **Auto-complete on the last checkbox** — checking off every subtask
   finishes the suggestion and awards XP in the same transaction as the
   toggle, no separate "Complete" tap.

## Data model

`aiCache/{userId}` document, `challenges[i]` shape grows from:

```ts
{ title: string; description: string; xpReward: number; status: 'suggested' | 'accepted' | 'completed' }
```

to:

```ts
{
  title: string;
  description: string;
  xpReward: number;
  status: 'suggested' | 'accepted' | 'completed';
  subtasks?: { title: string; completed: boolean }[]; // absent until accepted; present once generated
}
```

Subtasks have no `id` — the array index (`subIndex`) is their stable
identity, consistent with how the suggestion's own identity is its index in
`challenges` (documented in the original `2026-08-05-actionable-ai-suggestions-design.md`).

## Backend changes (`backend/services/ai.service.js`)

### 1. Single-select invariant in `acceptChallenge` (lines 225-250)

Inside the existing transaction, before flipping `status` to `'accepted'`,
reject if any *other* entry is already past `'suggested'`:

```js
async function acceptChallenge(userId, index) {
  const aiRef = db.collection('aiCache').doc(userId);

  return db.runTransaction(async (tx) => {
    const aiSnap = await tx.get(aiRef);
    if (!aiSnap.exists) throw new AppError('Suggestions not found', 404);

    const data = aiSnap.data();
    if (data.date !== todayStr()) throw new AppError('Suggestions not found', 404);

    const challenge = data.challenges?.[index];
    if (!challenge) throw new AppError('Suggestion not found', 404);

    const status = challenge.status ?? 'suggested';
    if (status !== 'suggested') {
      return { status };
    }

    const alreadySelected = data.challenges.some(
      (c, i) => i !== index && (c.status ?? 'suggested') !== 'suggested'
    );
    if (alreadySelected) {
      throw new AppError('Another suggestion has already been selected today', 409);
    }

    const updatedChallenges = data.challenges.map((c, i) =>
      i === index ? { ...c, status: 'accepted' } : c
    );
    tx.update(aiRef, { challenges: updatedChallenges });

    return { status: 'accepted' };
  });
}
```

Race safety: the Firestore transaction reads the whole array and retries on
contention, so two concurrent accept taps on different indices can't both
succeed — one will re-read the other's committed `'accepted'` status and 409.

### 2. `generateSubtasks(userId, index)` — new function

Mirrors `generateChallenges` (lines 195-218): builds a prompt from the
*specific* suggestion's title/description, calls the same `callAI` fallback
chain, parses, and persists.

```js
const DEFAULT_SUBTASKS = [
  'Initiate the protocol immediately.',
  'Execute without interruption.',
  'Log completion status.',
];

function buildSubtasksPrompt(challenge) {
  return `${VOICE_INSTRUCTION}

Protocol: ${challenge.title}
Directive: ${challenge.description}

Break this protocol into 3 to 5 concrete, sequential action steps as a JSON array of strings. Return ONLY the JSON array, no explanation, no markdown:
["step one", "step two", "step three"]

Constraints:
- Each step: one short imperative sentence, approved vocabulary, no punctuation beyond a period
- Steps must be concrete actions the hunter physically does, not restatements of the goal`;
}

function parseSubtasksJSON(text) {
  const match = text.match(/\[[\s\S]*?\]/);
  if (!match) return null;
  const parsed = JSON.parse(match[0]);
  if (!Array.isArray(parsed) || parsed.length === 0) return null;
  return parsed.slice(0, 5).map((title) => ({ title: String(title).trim(), completed: false }));
}

async function generateSubtasks(userId, index) {
  const aiRef = db.collection('aiCache').doc(userId);
  const snap = await aiRef.get();
  if (!snap.exists) throw new AppError('Suggestions not found', 404);

  const data = snap.data();
  if (data.date !== todayStr()) throw new AppError('Suggestions not found', 404);

  const challenge = data.challenges?.[index];
  if (!challenge) throw new AppError('Suggestion not found', 404);
  if (challenge.status !== 'accepted') {
    throw new AppError('Suggestion must be accepted before generating a checklist', 409);
  }
  if (challenge.subtasks) return challenge.subtasks; // idempotent — already generated

  const prompt = buildSubtasksPrompt(challenge);
  const raw = await callAI(prompt, JSON.stringify(DEFAULT_SUBTASKS));

  let subtasks;
  try {
    subtasks = parseSubtasksJSON(raw);
    if (!subtasks) throw new Error('Empty parse');
  } catch {
    logger.error('[AI] Subtask parse failed, using default');
    subtasks = DEFAULT_SUBTASKS.map((title) => ({ title, completed: false }));
  }

  await db.runTransaction(async (tx) => {
    const freshSnap = await tx.get(aiRef);
    const freshData = freshSnap.data();
    // Re-check status hasn't changed (e.g. suggestion switched) between the AI call and this write
    if (freshData.date !== todayStr() || freshData.challenges?.[index]?.status !== 'accepted') return;
    const updated = freshData.challenges.map((c, i) => (i === index ? { ...c, subtasks } : c));
    tx.update(aiRef, { challenges: updated });
  });

  return subtasks;
}
```

The AI call happens *outside* the transaction (external I/O shouldn't run
inside a retryable transaction body), with a narrow re-check transaction
after to write the result — if the suggestion is no longer `'accepted'` by
the time the AI responds (e.g. some other flow changed it), the write is
silently skipped rather than corrupting state.

### 3. `toggleSubtask(userId, index, subIndex)` — new function

```js
async function toggleSubtask(userId, index, subIndex) {
  const aiRef = db.collection('aiCache').doc(userId);
  const userRef = db.collection('users').doc(userId);

  const result = await db.runTransaction(async (tx) => {
    const [aiSnap, userSnap] = await Promise.all([tx.get(aiRef), tx.get(userRef)]);
    if (!aiSnap.exists) throw new AppError('Suggestions not found', 404);
    if (!userSnap.exists) throw new AppError('User not found', 404);

    const data = aiSnap.data();
    if (data.date !== todayStr()) throw new AppError('Suggestions not found', 404);

    const challenge = data.challenges?.[index];
    if (!challenge) throw new AppError('Suggestion not found', 404);
    if (challenge.status === 'completed') {
      throw new AppError('Suggestion already completed', 409);
    }
    if (challenge.status !== 'accepted' || !challenge.subtasks?.[subIndex]) {
      throw new AppError('Subtask not found', 404);
    }

    const updatedSubtasks = challenge.subtasks.map((s, i) =>
      i === subIndex ? { ...s, completed: !s.completed } : s
    );
    const allComplete = updatedSubtasks.every((s) => s.completed);

    if (!allComplete) {
      const updatedChallenges = data.challenges.map((c, i) =>
        i === index ? { ...c, subtasks: updatedSubtasks } : c
      );
      tx.update(aiRef, { challenges: updatedChallenges });
      return { subtasks: updatedSubtasks, completed: false };
    }

    // Last box checked — auto-complete and award XP, same as completeAISuggestion
    const { updates, result: xpResult } = computeXpGain(userSnap.data(), challenge.xpReward);
    const updatedChallenges = data.challenges.map((c, i) =>
      i === index ? { ...c, subtasks: updatedSubtasks, status: 'completed' } : c
    );
    tx.update(aiRef, { challenges: updatedChallenges });
    tx.update(userRef, updates);

    return { subtasks: updatedSubtasks, completed: true, xp: xpResult };
  });

  if (result.completed) {
    evaluateTitles(userId).catch((e) => logger.error({ err: e, userId }, 'Title evaluation failed'));
    updateUserRank(userId).catch((e) => logger.error({ err: e, userId }, 'Rank update failed'));
  }

  return result;
}
```

`completeAISuggestion` (lines 258-298) is left as-is — it remains reachable
only as a fallback for a suggestion whose `subtasks` never populated (total
AI failure with an empty default list edge case), so it isn't dead code, just
rarely hit.

### 4. Routes (`backend/routes/aiRoutes.js`)

Two new routes alongside the existing accept/complete routes (lines 51-69):

```js
// POST /api/ai/challenges/:index/subtasks
router.post('/challenges/:index/subtasks', asyncHandler(async (req, res) => {
  const index = Number(req.params.index);
  if (!Number.isInteger(index) || index < 0) {
    return res.status(400).json({ error: 'index must be a non-negative integer' });
  }
  const subtasks = await generateSubtasks(req.userId, index);
  res.json({ subtasks });
}));

// PATCH /api/ai/challenges/:index/subtasks/:subIndex/toggle
router.patch('/challenges/:index/subtasks/:subIndex/toggle', asyncHandler(async (req, res) => {
  const index = Number(req.params.index);
  const subIndex = Number(req.params.subIndex);
  if (!Number.isInteger(index) || index < 0 || !Number.isInteger(subIndex) || subIndex < 0) {
    return res.status(400).json({ error: 'index and subIndex must be non-negative integers' });
  }
  const result = await toggleSubtask(req.userId, index, subIndex);
  res.json(result);
}));
```

## Frontend changes

### `frontend/lib/api.ts`

- `AISuggestion` (lines 496-501) gains `subtasks?: { title: string; completed: boolean }[]`.
- New functions alongside `acceptAISuggestion`/`completeAISuggestion` (lines 162-173):
  - `generateSubtasks(index: number): Promise<{ subtasks: {title:string;completed:boolean}[] }>` → `POST /api/ai/challenges/${index}/subtasks`
  - `toggleSubtask(index: number, subIndex: number): Promise<{ subtasks: {...}[]; completed: boolean; xp?: {...} }>` → `PATCH /api/ai/challenges/${index}/subtasks/${subIndex}/toggle`

### `frontend/components/ChallengeSection.tsx`

- `ChallengeSection` computes `const selectedIndex = aiSuggestions.findIndex((s) => s.status !== 'suggested')` and passes `isLocked={selectedIndex !== -1 && selectedIndex !== i}` to each `SuggestionCard`.
- `SuggestionCard`:
  - `handleClick` on a `'suggested'` card: unchanged call to `acceptAISuggestion`, but on success additionally calls `generateSubtasks(index)` and stores the result via a new `onSubtasksGenerated(index, subtasks)` callback, with a loading flag shown between the two calls (a 3-row skeleton, matching the existing skeleton pattern in `ChallengeSection`'s `loading` branch at lines 47-63).
  - Once `suggestion.subtasks` is populated and `status === 'accepted'`, render a nested checklist instead of the "Tap to complete" hint (line 302-304 today): a list of small rows, each its own tappable element calling a new `onToggleSubtask(index, subIndex)` prop that hits `toggleSubtask` and updates local state from the response. If the response has `completed: true`, call the existing `onCompleted(index)` + `refreshProfile()` path exactly like the current complete flow (lines 258-260).
  - `isLocked` cards render with the same disabled visual treatment as `isCompleted` (`border-border/30 bg-surface/30 cursor-default`) but without the checkmark icon — just dimmed and inert, no click handler.
  - The outer element stops being one giant button once `subtasks` exist: it becomes a non-interactive container (`div`) with the checklist rows as the only interactive children, since the whole-card tap no longer means anything once acceptance already happened.

## Testing

Backend (`backend/__tests__/aiChallengeActions.test.js`, extending the
existing suite):
- `acceptChallenge`: accepting index 0 then attempting to accept index 1 → 409, index 1 still `'suggested'`.
- `generateSubtasks`: mocked `callAI` returning valid JSON → 3-5 subtasks with `completed: false`; malformed AI response → falls back to `DEFAULT_SUBTASKS`; calling on a `'suggested'` (not yet accepted) suggestion → 409; calling twice returns the same cached subtasks instead of regenerating (idempotent).
- `toggleSubtask`: toggling one of several subtasks → `completed: false` in response, XP unchanged; toggling the last remaining unchecked subtask → `completed: true`, XP awarded via `computeXpGain`, suggestion `status` becomes `'completed'`; toggling on an already-completed suggestion → 409; invalid `subIndex` → 404.

Frontend: extend or add a test file for `ChallengeSection`/`SuggestionCard`
covering: the sibling card is disabled once one is accepted; the checklist
renders after subtasks arrive; checking the last subtask transitions the
card to the completed visual state.

## Out of scope

- No ability to dismiss/reject a suggestion (unchanged from the original spec).
- No editing/regenerating an already-generated checklist.
- No changes to how the 2 daily suggestions themselves are generated (`generateChallenges`) — only what happens after one is picked.
